# gh-heatmap — design spec (v1)

Your GitHub contribution graph as your macOS desktop wallpaper: green squares on black
by default, or one of five built-in themes (§7), refreshed every 10 minutes by a per-user
launchd job. Written in
Python so the owner can audit every line.

Non-goals for v1: setting every Space at once (no public API; §8), headline text, custom
(user-defined) themes, Linux, a resident daemon by default (the Space watcher in §13 is opt-in).

## 1. Principles

- **Minimal and auditable.** One main file. Exactly two direct dependencies
  (`pillow`, `pyobjc-framework-Cocoa`; the latter pulls `pyobjc-core`). Everything
  else is the standard library. No shelling out at runtime except `launchctl`
  inside `install.py`/`uninstall.py`.
- **No secrets.** No GitHub token. Reads only the public page
  `https://github.com/users/<username>/contributions`.
- **No resident process by default.** Each run: fetch → parse → render → set wallpaper → exit.
  launchd starts it every 10 minutes. Most runs do no work (see §5). The one exception is
  the opt-in Space watcher (§13): a small process that waits for a public AppKit
  notification and makes no network requests.
- **Public API only.** Wallpapers are read and set only through documented AppKit /
  Foundation calls; no private frameworks and no reading or writing Apple's own
  wallpaper or Spaces files.
- **Fail safe.** Any error leaves the current wallpaper untouched, logs one line,
  and exits. Never draw an empty graph on bad data.
- **Everything under `$HOME`.** No sudo, no system files, no shell-rc edits.

## 2. Layout

```
~/Desktop/Desktop/ghm/        # project root (this repo)
  SPEC.md                     # this file
  README.md                   # short usage + audit pointers
  pyproject.toml              # requires-python >=3.13; deps: pillow, pyobjc-framework-Cocoa
  .python-version             # 3.14

  heatmap.py                  # the tool (single file)
  install.py                  # uv sync, first run, write + load LaunchAgent
  uninstall.py                # unload agent, restore wallpaper, delete owned files
  .venv/                      # created by `uv sync`; the LaunchAgent runs .venv/bin/python
```

Runtime files (all created by `heatmap.py`):

```
~/Library/Application Support/gh-heatmap/

                       `heatmap.py --theme`; "theme" is absent for the default look
  state.json           see §6
  backup.json          original wallpaper per display, captured once, before first change
  heatmap-<hash>.png   rendered wallpapers (current, previous, live, and up to 50 more
                       from the last 14 days kept; the rest pruned, see §6)
~/Library/Application Support/gh-heatmap.lock
                       flock file, held for the whole of every run (including --uninstall).
                       It sits NEXT TO the support dir, never inside it, and is never
                       deleted (uninstall leaves this one empty file). If it lived inside
                       the deleted tree, a run starting after the rmtree could lock a fresh
                       inode while --uninstall still held the old one.
~/Library/Logs/gh-heatmap.log          RotatingFileHandler, 512 KiB × 3
~/Library/Logs/gh-heatmap.launchd.log  launchd stdout/stderr (should stay empty)
~/Library/LaunchAgents/local.gh-heatmap.plist
~/Library/LaunchAgents/local.gh-heatmap.spaces.plist   only with install.py --watch-spaces (§13)
```

## 3. `heatmap.py` CLI

```
heatmap.py                 scheduled run (what launchd calls)
heatmap.py --user NAME     override config.json username for this run only (never saved)
heatmap.py --theme NAME    change the theme: save it in config.json (under the lock), then run as
                           usual, so it applies now. Case-insensitive; `default` removes the saved
                           theme. Needs an installed config.json (exit 1 otherwise; it never
                           creates one). Not allowed with --restore / --uninstall.
heatmap.py --list-themes   print the five theme names, one per line, and exit 0. Handled before
                           logging starts: reads and writes no files, takes no lock
heatmap.py --dry-run       fetch + render to ~/Library/Application Support/gh-heatmap/preview.png; do NOT set wallpaper.
                           With --theme NAME, previews that theme and saves nothing
heatmap.py --force         ignore ETag and up-to-date checks; re-render and re-apply on every
                           display; still honours a recorded GitHub backoff and falls back to
                           cached data if the network fails
heatmap.py --restore       restore the wallpaper(s) saved in backup.json; deletes nothing
heatmap.py --uninstall     restore, verify no screen shows our image, then delete all our
                           files, all under one lock (used by uninstall.py; §11)
heatmap.py --watch-spaces  stay running; after each active-Space change, re-apply the cached
                           graph (§13). No other options allowed. What the opt-in watcher
                           agent runs
```

Exit codes:

| code | meaning |
|------|---------|
| 0 | success: applied or already up to date on every screen; `--dry-run` wrote the preview; `--restore` restored everything (or there was no backup.json); `--uninstall` deleted everything; `--list-themes`; `--watch-spaces` stopped, or found nothing installed |
| 1 | error, including: `--dry-run` wrote no preview (backoff window, 429/503); `--restore` could not restore every screen; any screen failed; `--uninstall` kept the files (a screen still shows our image, or no screen to verify); an unknown theme (given or saved); `--theme` with no config.json; any usage error (argparse is made to exit 1, because 2 means "skipped") |
| 2 | skipped gracefully (scheduled run): no screens, inside a GitHub backoff window, or the lock is busy |
| 3 | `--restore` / `--uninstall` only: the lock is busy (uninstall.py waits and retries) |

install.py relies on these codes to verify the first run (§10).

`--theme NAME` on a real run: the username and theme are validated first (any failure is
exit 1 with nothing written), then the theme is saved, then the run proceeds as usual and
its exit code is returned unchanged. A saved theme never turns 1 or 2 into 0: if the run
is skipped (2) or a screen fails (1), the next successful run applies the saved theme.

Config and theme are read once per run, after `--restore` / `--uninstall` have been
dispatched (those never read config.json, so a bad theme cannot block recovery) and
before the backoff check, fetch or any `state.json` write. An unknown saved theme is
exit 1, never a silent fall back to the default.
Logging: `logging` to the rotating file; also to stderr when stderr is a TTY.

## 4. Fetch

- Validate username against `^[A-Za-z0-9](?:[A-Za-z0-9-]{0,38})$` before building the URL.
- One `urllib.request` GET to `https://github.com/users/<username>/contributions`,
  headers: `User-Agent: gh-heatmap/1 (personal wallpaper script)`, and
  `If-None-Match: <etag>` when `state.json` has one.
- `timeout=15`. Read at most 2 MiB (`read(MAX+1)`, error if over).
- Redirects are followed by a `urllib.request.HTTPRedirectHandler` subclass (installed
  with `build_opener`) that raises for any target not starting with
  `https://github.com/`. The final URL is checked again, and an `HTTPError` is only
  treated specially (304/429/503) if its `geturl()` is on `https://github.com/`.
- `304 Not Modified` → use `state.json["cells"]` (cached parse).
- `429` or `503` → read `Retry-After` (seconds; default 1800; floor 60; ceiling
  24 h, accepted policy so one bad header can't stop updates for longer than a day),
  store `state.json["retry_until"]`, exit 2. On every run, if `now < retry_until`, exit 2
  immediately without a request (`--dry-run`: exit 1, no preview).
- Any other network/HTTP error → log, and if `state.json["cells"]` exists continue
  with cached cells (a display change may still need a re-render); otherwise exit 1.
- "Skip if no network" is just this request failing fast. No separate probe.
- Before the request, a scheduled run checks `NSScreen.screens()`; if it is empty it
  exits 2 without fetching (§8).
- `state.json` also records `username`; cached `etag`/`cells` are dropped when it changes.

## 5. Parse

Use `html.parser.HTMLParser` from the stdlib (not regex). Collect every `<td>`
whose attributes include both `data-date` and `data-level`:
`cells: dict[str, int]` mapping ISO date → level.

Validate, and raise on failure (keep previous wallpaper):

- every level is an int in 0–4; every date parses with `date.fromisoformat`
- 7 ≤ count ≤ 378
- dates are contiguous (sorted, each exactly 1 day after the previous)
- max date ≤ today + 1 day (timezone slack)

**Layout is by date, not by document order.** GitHub's HTML lists cells
weekday-major (all Sundays, then all Mondays, …). For each date:

```
start_sunday = first_date - timedelta(days=(first_date.weekday() + 1) % 7)
days = (date - start_sunday).days
col  = days // 7          # week
row  = days % 7           # 0 = Sunday … 6 = Saturday
ncols = max(col) + 1
```

Cells not present (edge padding) are simply not drawn.

## 6. State and change detection

`state.json` (written atomically: temp file in same dir + `os.replace`):

```json
{
  "etag": "W/\"...\"",
  "cells": {"2025-11-02": 1, ...},
  "fetched_at": "2026-11-04T17:00:00Z",
  "retry_until": null,
  "applied": {"<display_id>": "<render_hash>"},
  "applied_prev": {"<display_id>": "<previous render_hash>"},
  "backup_not_needed": false,
  "username": "jballo",
  "version": 1
}
```

`render_hash = sha256(json.dumps({"cells": cells, "w": W, "h": H,
"style": STYLE_VERSION, "theme": THEME}, sort_keys=True))[:16]`, where `THEME` is the
resolved colours (`{"background", "levels"}`), not the name, so changing theme or
editing a palette re-renders every display. `STYLE_VERSION` is a module constant; bump
it whenever rendering output changes in a way the inputs above don't capture.

Per display, per run:

1. Compute `render_hash` for that display's backing size.
2. Current wallpaper path = `NSWorkspace.desktopImageURLForScreen_(screen).path()`.
3. Skip the display if `applied[display_id] == render_hash` **and** the PNG exists
   **and** the current wallpaper path equals that PNG (so a failed/overridden set
   gets redone; a manual wallpaper change by the user is overridden — that's the
   tool's job). `--force` bypasses this.
4. Else: render (if the PNG doesn't exist, or `--force`), set, then record
   `applied[display_id]`; if that replaces a different hash, the old one is stored in
   `applied_prev[display_id]`. Record only after `setDesktopImageURL…` returned success.
   Steps 1–4 for one screen (display id, backing size, current path, hash, render, set)
   run inside that screen's own error boundary: a failure is logged, that screen's state
   is unchanged, the other screens still run, and the run exits 1.
5. After all displays, prune `heatmap-*.png`. Protected: every PNG named by `applied`,
   every PNG named by `applied_prev`, and every one of ours that is the live wallpaper of
   any screen, both in the snapshot taken before this run and freshly queried from every
   screen at prune time. If either screen query fails, skip pruning entirely.
   Protected PNGs are never deleted and never count against the cap below.
   Of the unprotected rest, also keep the `RETAIN_EXTRA` (50) newest whose own mtime
   (`os.lstat`, symlinks not followed) is within `RETAIN_DAYS` (14 days); ties broken by
   file name. A PNG whose mtime can't be read is kept. Everything else is deleted.
   Why: we can only see each screen's *current* Space (§8), but other Spaces, and
   displays that are not connected, keep pointing at the PNG they last showed. A new PNG
   appears whenever the graph's levels, its date window, the screen size or the theme
   change, so keeping only current + previous left most other Spaces pointing at deleted
   files. Retention makes that rare; it can't rule it out (a Space left alone for more
   than 14 days or 50 renders can still point at a deleted PNG). PNGs are ~32 KB, so
   the cap costs under ~2 MB. mtime is the render time; it is never touched afterwards.
   So the 14 days count from when a PNG was rendered, not from when a Space last showed
   it: a PNG reused without re-rendering (step 4) keeps its old mtime and can be pruned
   as soon as it stops being protected.

Concurrency: `fcntl.flock(LOCK_EX | LOCK_NB)` on `gh-heatmap.lock` (§2; its parent dir is
created first); if busy, log and exit 2
(`--restore`: exit 3). `--dry-run` takes no lock: it writes only `preview.png` and the
log, and never writes `state.json` or `config.json`. `--list-themes` takes no lock and
touches no files. `heatmap.py --theme` and `install.py` read and rewrite `config.json` only
while holding this lock, so neither can lose the other's update.

## 7. Render (Pillow, imported lazily only when a render is needed)

- Backing size per screen: `r = screen.convertRectToBacking_(screen.frame())`,
  `W, H = int(r.size.width), int(r.size.height)`.
- Grid occupies ~62 % of W: `pitch = 0.62 * W / ncols`; square `size = 0.76 * pitch`;
  `radius = 0.22 * size`; grid is centred horizontally and vertically.
- Colours come from the theme: a background plus levels 0–4 (`DEFAULT_THEME` /
  `THEMES` in heatmap.py; every one passes `validate_theme`: exactly the keys
  `background` and `levels`, 5 levels, all lowercase `#rrggbb`).

  | theme | background | 0 | 1 | 2 | 3 | 4 |
  |-------|------------|---|---|---|---|---|
  | (default, GitHub dark) | `#000000` | `#1b2a1f` | `#0e4429` | `#006d32` | `#26a641` | `#39d353` |
  | `dracula` | `#282a36` | `#44475a` | `#5c4f7a` | `#7a64a1` | `#9c7cce` | `#bd93f9` |
  | `gruvbox` | `#282828` | `#3c3836` | `#734723` | `#9e5820` | `#cf6d1c` | `#fe8019` |
  | `nord` | `#2e3440` | `#3b4252` | `#4e6572` | `#60818f` | `#74a1b0` | `#88c0d0` |
  | `panda` | `#292a2b` | `#373b41` | `#74445b` | `#9f5377` | `#d06497` | `#ff75b5` |
  | `tokyo-night` | `#1a1b26` | `#292e42` | `#3c4a6f` | `#4f6599` | `#6584c9` | `#7aa2f7` |

  For the built-ins, the background, level 0 and level 4 are the palette's official
  colours (Dracula: Background / Current Line / Purple; Gruvbox dark: bg0 / bg1 / bright
  orange; Nord: nord0 / nord1 / nord8; Panda: background-light / gray / pink; Tokyo
  Night: bg / bg_highlight / blue). Levels 1–3 are level 4 blended into the background
  at 35 / 55 / 78 %. Level 0 is always distinct from the background so the empty grid
  still reads as a grid.
- `ImageDraw.rounded_rectangle` per cell. Save PNG with `optimize=True` to a temp
  file, then `os.replace` to `heatmap-<render_hash>.png`.

## 8. Wallpaper (PyObjC)

```python
from AppKit import NSScreen, NSWorkspace
from Foundation import NSURL
ws = NSWorkspace.sharedWorkspace()
ok, err = ws.setDesktopImageURL_forScreen_options_error_(NSURL.fileURLWithPath_(path), screen, {}, None)
```

- Must run on the main thread (it does; the script is single-threaded).
- Display id: `screen.deviceDescription()["NSScreenNumber"]` (int). Used as the
  key in `applied` and `backup.json`.
- If `NSScreen.screens()` is empty (login window, display asleep): log, exit 2. This is
  checked before the fetch, so no request is made when nothing could be set.
- Check `ok`; on failure raise with `err` and leave state unchanged for that display.
- **Read-back lag.** macOS applies a wallpaper change asynchronously. For hundreds of ms
  after a successful set (observed: still stale 175 ms after a restore),
  `desktopImageURLForScreen_` can keep returning the *old* path. So every read that
  follows a set polls `wallpaper_path()` every 0.25 s, comparing by `realpath`:
  - after setting a heatmap: up to 2 s, so a run seconds later sees it as up to date
    (scheduled and manual runs; the Space watcher skips this wait, §13).
    If it never settles, log at debug only; the set succeeded. The up-to-date skip rule
    itself is unchanged.
  - These post-set waits are read-only and are wrapped in their own exception boundary:
    if the read-back itself raises, log a warning and carry on, because the set already
    succeeded and was recorded. (The uninstall verification is different: there a read
    error must propagate, so a failed read can never count as "not ours".)
  - after each restore in `--restore`/`--uninstall`: up to 5 s for the restored path. If
    it never shows up, log a warning and carry on; the set succeeded.
  - in `--uninstall` verification (§11): up to 5 s for a display that reads as ours to
    stop being ours, before it counts as "still ours".
- Known limit (documented in README): this sets the wallpaper for the *current
  Space* on each screen only. Apple has no public API for all Spaces, or to list
  other Spaces' wallpapers. Another Space (or a display that is not connected) keeps
  its old heatmap until a run finds it current: normally the next successful run
  while you are on that Space, but a GitHub backoff, sleep, a busy lock or a failed
  run can delay that. A successful run by hand updates the current Space at once (the
  same backoff and lock rules apply, also with `--force`).
  Retention in §6 step 5 keeps the PNGs those Spaces point at for a while, and the
  opt-in Space watcher (§13) updates a Space shortly after you switch to it.

## 9. Backup and restore

- At the start of every scheduled run that reaches the screens, before any screen is
  touched, `backup.json` is **merged**: for each connected screen that has no entry yet
  and whose current wallpaper is not one of ours, append
  `{"display": id, "path": current path or null, "options": {...}}`, where options are
  `desktopImageOptionsForScreen_` filtered to JSON-safe values (int/float/bool/str; drop
  NSColor etc.). Existing entries are never modified (so reinstalls keep the real
  original), and a display first connected later still gets its original saved. Don't
  write an empty backup. `state.json["backup_not_needed"]` is `true` only when
  `backup.json` has no entries and none were added because every connected screen
  already shows one of ours; otherwise `false`. If any screen can't be read, or
  `backup.json` is invalid, change nothing and exit 1.
- **Validation.** A missing `backup.json` means "no backup". An existing one must be a
  list. Each entry must be an object with `display` (int), `path` (string or null) and
  `options` (object whose values are int/float/bool/str), and display ids must not
  repeat. `{}`, `null`, `false`, or an entry missing a key all fail. On any violation the
  scheduled run exits 1 before touching a screen, and `--restore`/`--uninstall` exit 1
  without changing or deleting anything.
- **"Ours".** A path is ours if, as written (directory resolved, final name not
  followed), it is inside the support dir, **or** its full `realpath` is. So a symlink
  `gh-heatmap/heatmap-x.png -> /elsewhere/original.png` counts as ours. Restore, uninstall
  verification and prune all use this rule. Prune compares both forms on both sides.
- `--restore`: for each entry, match the display by id (fall back to the only screen
  only if exactly one screen is connected **and** `backup.json` has exactly one entry;
  with several entries, never guess). If `path` exists on disk and is not inside
  our support dir, `setDesktopImageURL…(path, screen, options)`. Otherwise (dynamic
  wallpaper, slideshow, missing file, unknown display) open the Wallpaper settings
  pane once via `ws.openURL_(NSURL.URLWithString_("x-apple.systempreferences:com.apple.Wallpaper-Settings.extension"))`
  and tell the user to re-pick. Restore is best-effort for static images; say so.
  Keep `backup.json` if any restore failed, and exit 1. Exit 3 if the lock is busy.
  `--restore` never deletes anything.
- Uninstall (§11) refuses to delete anything while any connected display still shows
  one of our images, since deleting it would leave that display pointing at a missing file.

## 10. `install.py`

```
install.py --user NAME [--theme NAME] [--interval 600] [--watch-spaces | --no-watch-spaces]
```

1. Validate username (same regex) and `--theme` (case-insensitive; one of
   `THEME_NAMES`, which must match `heatmap.py --list-themes`, or `default`). Both are
   checked before anything else, so a bad name changes nothing. Require `uv` on PATH
   (`shutil.which`).
2. `uv sync --locked` in the project dir (uses `uv.lock` exactly; fails if the lock
   is missing or out of date with `pyproject.toml` — that is the hash-pinning guarantee.
   `--frozen` would not detect a stale lock).
3. Create the support dir. Take the lock (§6; retry every 2 s, about 30 s, then exit 1),
   write `config.json` atomically, release the lock (the first run takes it itself).
   Theme: `--theme NAME` if given (`default` = none). Otherwise a reinstall keeps the
   theme saved in the existing config.json, lowercased; if that file is unreadable, not
   a JSON object, or its theme is not a known name, it prints a warning and uses the
   default instead of failing.
4. First run by hand: `.venv/bin/python heatmap.py`. It must exit 0, and afterwards
   `backup.json` must exist or `state.json["backup_not_needed"]` must be `true` (every
   screen's wallpaper was already ours). Otherwise abort before writing the plist
   (exit 2 is reported as "skipped, try again later"). This captures `backup.json` and
   surfaces any error before anything is scheduled.
5. Write the plist with `plistlib` (temp + replace) to
   `~/Library/LaunchAgents/local.gh-heatmap.plist`:
   ```
   Label              local.gh-heatmap
   ProgramArguments   [<abs .venv/bin/python>, <abs heatmap.py>]
   WorkingDirectory   <abs project dir>
   EnvironmentVariables {"PATH": "/usr/bin:/bin"}
   StartInterval      600          (note: fires missed during sleep are dropped; next
                                    run is ≤10 min after wake — acceptable)
   RunAtLoad          true
   ProcessType        Background
   StandardOutPath / StandardErrorPath  ~/Library/Logs/gh-heatmap.launchd.log
   ```
   No `KeepAlive` (the script exits on purpose; no restart loops).
6. `launchctl bootout gui/$UID/local.gh-heatmap` (ignore failure), then
   `launchctl bootstrap gui/$UID <plist>` with `check=True`.
6a. Space watcher (§13): on with `--watch-spaces`; with no flag, keep what a previous
   install chose (its plist exists or not). If on: `bootout
   gui/$UID/local.gh-heatmap.spaces` (ignore failure), write
   `~/Library/LaunchAgents/local.gh-heatmap.spaces.plist`, `bootstrap` it; if that
   bootstrap fails, delete the plist and exit 1 saying the main agent is installed but
   the watcher is not. `--no-watch-spaces` is not handled here but right after step 1
   (bootout, delete the plist), before `uv sync`, so turning the watcher off never
   depends on the first run or GitHub.
7. Print what was installed and how to uninstall.

## 11. `uninstall.py`

uninstall.py is standard-library only, so it can't check what is on screen. All the
safety-critical work is therefore done by `heatmap.py --uninstall`. uninstall.py never
deletes the support dir or logs itself.

`uninstall.py`:

1. `launchctl bootout gui/$UID/local.gh-heatmap` and `gui/$UID/local.gh-heatmap.spaces`
   (ignore failures). The watcher must be stopped before restoring, or a Space switch
   would put the heatmap back.
2. Delete both plists. Steps 1–2 always happen, so nothing runs again.
3. If `.venv/bin/python` is missing: say that the wallpaper can't be restored or verified
   safely, print the original paths from `backup.json` (plain JSON read), tell the user
   to run `uv sync --locked` and then uninstall.py again, and exit 1 with everything else
   left in place.
4. Otherwise run `heatmap.py --uninstall`. On exit 3 (lock busy) wait 2 s and retry, up
   to 15 attempts, with no wait after the last one. Propagate its exit code. If it is
   nonzero, print "cleanup may be incomplete; check these paths:" followed by the lock
   file, the support dir and each log file with whether it still exists, then the saved
   original paths.
5. On success, print that the source folder, `.venv` and the empty `gh-heatmap.lock`
   were left alone (delete the folder to remove everything).

`heatmap.py --uninstall` does everything under **one continuous flock**:

1. Take the lock (exit 3 if busy).
2. Restore from `backup.json` exactly as `--restore` does (same code; best-effort).
3. Re-query every connected screen. If none is connected, it can't verify: delete
   nothing and exit 1. A screen whose wallpaper reads as ours (§9 rule: as written or
   resolved) gets up to 5 s, polled every 0.25 s, to report something else, because macOS
   reports a just-restored wallpaper late (§8). Each restore also waits up to 5 s for its
   own path first. If any screen is still ours after its wait, delete nothing: print which displays still show ours, tell the
   user to re-pick a wallpaper on them and run uninstall.py again, and exit 1.
   The Wallpaper settings pane is opened once if anything failed to restore or still shows ours.
4. Only if no screen shows ours: close the logging handlers, then, still holding the
   lock, delete the support dir and the log files (`gh-heatmap.log`, its rotated
   `.1`–`.3`, `gh-heatmap.launchd.log`). `gh-heatmap.lock` is outside the support dir and
   is never deleted. Exit 0. If a deletion fails partway (e.g. a log unlink after the
   support dir is already gone), print "cleanup may be incomplete; check these paths:"
   with each path's current existence, and exit 1.

Re-running uninstall.py is safe and idempotent. Already-restored paths are just set
again, and verification then passes. After a successful run there is nothing left to
restore, so a later run deletes whatever remains.

## 12. Testing checklist (manual, before trusting it unattended)

1. `uv run heatmap.py --dry-run --user jballo` → open `preview.png`, check layout
   (most recent week at the right, Sunday on top).
2. `uv run heatmap.py --user jballo` → wallpaper changes; `backup.json` exists.
3. Run again → log says skipped (nothing changed), no new PNG.
3a. With 2+ desktops: on desktop 1 run `heatmap.py --force --theme nord`, then
    `--force --theme dracula`, then `--force --theme default` (`--force` re-renders, so
    each PNG's mtime is fresh). All three PNGs are still in the support dir (nothing
    pruned). Swipe to desktop 2 → it still shows its old image until a run happens there;
    `uv run heatmap.py` on desktop 2 updates it.
4. `install.py --user jballo` → `launchctl print gui/$UID/local.gh-heatmap` shows it loaded;
   wait ≤10 min, log shows a run from launchd.
4a. `install.py --user jballo --theme dracula` → Dracula on every display, config.json has
    `"theme": "dracula"`. `heatmap.py --theme nord` → Nord on every display now;
    `heatmap.py --theme default` → green, `"theme"` gone. Reinstall without `--theme` keeps
    the saved theme. `install.py --theme bogus` and `heatmap.py --theme bogus` exit 1 and
    change nothing.
4b. `install.py --user jballo --watch-spaces` → `launchctl print gui/$UID/local.gh-heatmap.spaces`
    shows it running; log says `watch: watching for Space changes`. With 2+ desktops:
    `heatmap.py --theme nord` on desktop 1, swipe to desktop 2 → Nord there right after
    the swipe ends (log: `set` within ~50 ms of the switch), and no fetch for it. Switch with the network off → still updates.
    `install.py --user jballo` (no flag) keeps the watcher; `--no-watch-spaces` removes it.
5. `uninstall.py` → original wallpaper back, no files left under `~/Library/*/gh-heatmap*` except the empty `~/Library/Application Support/gh-heatmap.lock`.

## 13. Space watcher (opt-in)

macOS has no public API to set every Space's wallpaper, but it does announce, through
public AppKit API, when the active Space changes. The watcher listens for that and
re-applies the graph, so the Space you switch to is updated as soon as you arrive
(measured on macOS 27.2: the wallpaper is set 40–65 ms after the notification) instead
of at the next scheduled run. What is still visible is macOS's own part: the
notification comes only once the swipe has finished, so the swipe shows the Space's
old image, and macOS then fades to the new one. Public API can't avoid either; only
setting a Space before you visit it could, and there is no public API for that. A busy
lock, several displays or system load can add delay.

- **Opt-in.** `install.py --watch-spaces` (§10 step 6a). The default install has no
  resident process (§1).
- **What runs.** LaunchAgent `local.gh-heatmap.spaces`:
  ```
  ProgramArguments   [<abs .venv/bin/python>, <abs heatmap.py>, --watch-spaces]
  WorkingDirectory   <abs project dir>
  EnvironmentVariables {"PATH": "/usr/bin:/bin"}
  RunAtLoad          true
  KeepAlive          {SuccessfulExit: false}   (restarted if it exits non-zero or crashes)
  ThrottleInterval   60                        (at most one restart a minute)
  StandardOutPath / StandardErrorPath  ~/Library/Logs/gh-heatmap.launchd.log
  ```
- **How.** `NSApplication.sharedApplication()` with activation policy *prohibited* (no
  Dock icon or menu bar), an observer for `NSWorkspaceActiveSpaceDidChangeNotification`
  on `NSWorkspace.sharedWorkspace().notificationCenter()`, then `NSApp.run()`. It must be
  NSApplication's own event loop: tested on macOS 27.2, a plain `NSRunLoop` (as
  PyObjC's `AppHelper.runConsoleEventLoop` gives) receives other NSWorkspace
  notifications but never this one. Nothing else is observed. Stopping uses
  `NSApp.stop_` plus a posted application-defined event so `run()` returns at once
  (`terminate_` would `exit()` and skip cleanup).
- **No debounce.** The refresh runs inside the notification callback. Measured on macOS
  27.2: `desktopImageURLForScreen_` already reports the new Space's wallpaper when the
  notification arrives, and a refresh whose PNG exists takes ~5 ms, so waiting would only
  add delay (a first version waited 1 s, which users noticed). Notifications that arrive
  during a refresh are queued by the run loop and each get their own cheap refresh.
- **No post-set wait.** The watcher passes `settle=False`, skipping the up-to-2 s
  read-back poll of §8 that scheduled runs do, so a slow read-back can't hold up the next
  Space change.
- **Refresh** (`refresh_from_cache`): take the lock non-blocking (§6). If busy, retry
  every 5 s, up to 12 tries, then wait for the next change. Under the lock: if
  `config.json` is gone, stop and exit 0 (so launchd doesn't restart it); else read the
  username and theme from it, load `state.json`, and if it has cached cells, run the
  normal per-display apply and prune (§6 steps 1–5) with them. It **never fetches**, so it
  makes no network request and is unaffected by a GitHub backoff; the scheduled run keeps
  the cache fresh. No cached cells yet: log and do nothing. Any error is logged and the
  watcher keeps running.
- **Errors.** Unlike a scheduled run (§1 "Fail safe": log and exit), the watcher logs a
  failed refresh, including a lock error, and keeps running; the next Space change
  tries again.
- **Exit.** 0 when not installed (no `config.json`, at start or at a refresh) or when
  stopped by SIGTERM (`launchctl bootout`, `launchctl kickstart -k`) or SIGINT. Those
  signals are routed through PyObjC's `MachSignals` to the run loop, so a refresh in progress finishes first, then
  the observer is removed and `watch: stopped` is logged. 1 on an unexpected error at
  start, or if the event loop ends without being asked to; launchd then restarts it
  after `ThrottleInterval`. If it is killed outright (SIGKILL), the kernel releases the
  lock and every state write is atomic, so that is safe too.
- **Cost.** Idle: no measurable CPU; it wakes for a notification, a pending lock-retry
  timer, or a signal, and has no periodic wakeup; ~85 MB resident (Python
  + AppKit; Pillow is imported only if a refresh has to render a new PNG, and then stays
  loaded).
- **Interactions.** `--restore` puts the original back only until the next run, now
  including the next Space switch; uninstall stops the watcher first (§11). Setting a
  wallpaper does not change the active Space, so a refresh can't trigger itself.
- **Limits.** It updates the Space you switch *to*. Spaces you don't visit, and displays
  that aren't connected, still keep their old image (§6 step 5 retention still applies).
- **Tried and rejected: one stable file for every Space.** If every Space pointed at the
  same path and we replaced that file's contents, Spaces might be current before you
  arrive. Tested on macOS 27.2 (4 desktops, all pointed at one file, then the file
  atomically replaced with a different image via temp + fsync + `os.replace`, no set
  call): neither the current desktop nor any other desktop changed, during or after the
  swipe. macOS keeps showing the image it already loaded. So with public API the
  arrival flash can't be avoided, and content-addressed file names stay. (In-place
  rewriting was not tried: a reader could see a half-written PNG, so it couldn't ship.)
